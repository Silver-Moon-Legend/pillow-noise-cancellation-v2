# 枕边降噪设备项目团队协作规范

## 1. 沟通机制

### 1.1 日常沟通
- **GitHub Issues**：技术问题和任务跟踪
- **GitHub Discussions**：技术讨论和设计决策
- **GitHub Commit Messages**：详细说明代码变更

### 1.2 定期会议
- **每周进度会议**：每周五下午2:00
- **技术讨论会议**：根据需要随时召开
- **里程碑总结会议**：每个里程碑完成后

### 1.3 紧急沟通
- 紧急问题使用GitHub Issues标签"urgent"
- 需要立即协调的问题发邮件或消息

## 2. 文档规范

### 2.1 文档结构
- `/docs/`目录存放所有项目文档
- 各专家在自己的专业目录下存放技术文档
- 项目经理在`/docs/`目录下存放管理文档

### 2.2 文档命名规范
- 中文命名，便于团队成员识别
- 使用统一格式：`功能描述_日期.md`
- 使用Markdown格式

### 2.3 文档更新频率
- **每日**：任务进度更新
- **每周**：技术文档更新
- **里程碑节点**：总结文档更新

## 3. 代码规范

### 3.1 代码提交规范
- 每次提交必须有详细的commit message
- 提交前必须通过代码审查（embedded-review）
- 每次提交关联到对应的GitHub Issue

### 3.2 分支管理
- **main分支**：稳定版本
- **feature分支**：功能开发
- **bugfix分支**：问题修复

### 3.3 代码审查流程
1. 提交Pull Request
2. 至少两人审查
3. 通过embedded-review技能审查
4. 合并到main分支

## 4. 任务管理

### 4.1 任务分配原则
- 每个任务必须有明确的负责人
- 每个任务必须有明确的开始和截止日期
- 每个任务必须有明确的输出要求

### 4.2 进度跟踪
- 每日更新任务进度百分比
- 每周提交进度报告
- 里程碑节点进行总结

### 4.3 问题解决流程
1. 发现问题 → 创建GitHub Issue
2. 讨论解决方案 → GitHub Discussions
3. 实施解决方案 → 代码提交
4. 验证解决方案 → 测试报告

## 5. 质量保证

### 5.1 代码质量
- 使用embedded-review技能进行代码审查
- 使用python-code-test技能进行算法测试
- 代码必须有测试用例

### 5.2 文档质量
- 文档必须清晰、完整
- 文档必须有版本控制
- 文档必须及时更新

### 5.3 测试质量
- 分阶段测试（算法→嵌入式→硬件→声学）
- 测试必须有详细记录
- 测试问题必须有跟踪和解决

## 6. 文件共享和协作

### 6.1 技术文件共享
- STM32CubeMX配置文件共享
- PCB设计文件共享
- 算法代码共享

### 6.2 设计决策记录
- 所有技术决策必须有记录
- 决策讨论必须有文档
- 决策变更必须有记录

## 7. 会议记录

### 7.1 会议纪要要求
- 会议必须有纪要
- 纪要必须上传到GitHub
- 纪要必须有任务分配和跟进

### 7.2 会议频率
- **项目经理**：每周组织进度会议
- **技术专家**：根据需要召开技术会议
- **交叉协作**：专家之间定期沟通会议

## 8. 紧急情况处理

### 8.1 紧急问题定义
- 影响项目进度的问题
- 影响产品质量的问题
- 影响团队协作的问题

### 8.2 紧急处理流程
1. 立即报告项目经理
2. 召开紧急会议
3. 制定应急方案
4. 实施应急方案

## 9. 激励机制

### 9.1 进度奖励
- 按时完成任务奖励
- 高质量完成任务奖励
- 创新解决方案奖励

### 9.2 惩罚机制
- 无故延期任务惩罚
- 低质量完成任务惩罚
- 违反协作规范惩罚

## 10. 更新频率
- 协作规范每月更新一次
- 根据项目进展调整规范
- 团队反馈及时纳入规范
